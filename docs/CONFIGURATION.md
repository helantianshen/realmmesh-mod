# 连接配置与服务器凭据

游戏实例首次启动后生成 `config/realmmesh/connection.toml`：

```toml
[rpc]
host = "127.0.0.1"
port = 9000
timeoutMillis = 2000
server_id = ""
server_secret = ""
```

| 字段 | 说明 |
| --- | --- |
| host | 中心主机名或 IP，不包含协议和端口 |
| port | 中心 gRPC 端口，范围 1–65535 |
| timeoutMillis | 单次请求超时毫秒数，范围 1–2147483647 |
| server_id | 中心登记返回的服务器 ID，必须使用带引号的十进制正整数字符串 |
| server_secret | 中心交付的 43 字符 Base64URL 原始密钥，不是数据库摘要 |

空凭据不会建立匿名 RPC 客户端。凭据格式或类型错误会中止本次游戏服务器启动，并输出固定诊断提示。host、port、timeoutMillis 的非法值由 NeoForge 配置系统处理并恢复默认值，TOML 语法错误也由原生配置系统处理。

配置在逻辑服务器启动时形成快照，修改文件后必须重启游戏服务器。配置使用 COMMON 类型，不向远端玩家同步；客户端安装 Mod 后生成的是它自己的本机配置。内置服配置属于运行内置服的本机用户。

## 凭据生命周期

中心管理员预先登记服务器并交付 ID 和原始密钥。原始密钥只在创建或轮换成功时交付，中心不提供恢复接口；丢失时重新轮换。

- 停用后，中心拒绝后续调用；重新启用后原密钥恢复可用。
- 轮换后，旧密钥失效；修改本机配置并重启才能使用新密钥。
- 删除后，该服务器凭据失效。

每次请求自动附带服务器身份、密钥、独立 request ID 和超时设置。当前使用明文 gRPC，没有 TLS；服务器凭据认证不提供链路加密。不要将密钥提交到版本库或发给其他玩家。

## 探测与排查

控制台执行 `realmmesh ping`，玩家执行 `/realmmesh ping`，要求权限等级至少为 2。玩家还必须先完成注册或登录，OP 也不能绕过认证门禁。命令异步执行，在服务器线程返回结果；不会向其他管理员广播结果。显示耗时包含整个调用，不是纯网络延迟。

| 现象 | 检查内容 |
| --- | --- |
| 提示检查配置与凭据 | 字段类型、ID、原始密钥是否正确，修改后是否重启 |
| UNAUTHENTICATED | 中心是否停用或删除服务器，密钥是否已轮换 |
| UNAVAILABLE | 中心进程、地址、端口与网络连通性 |
| DEADLINE_EXCEEDED | 中心响应、网络状况和 timeoutMillis 设置 |

游戏服启动时依次等待带凭据的 Echo 与配置拉取，每次沿用 timeoutMillis 上限。任一步失败均中止启动并关闭连接，不使用本地默认值或旧缓存；管理员修正原因后重新启动。内置服的中心检查失败通过客户端适配退出本次世界加载，不强制关闭客户端。停服关闭客户端；玩家退出或服务器停止后的迟到反馈会被丢弃。

运行期间每 30 秒异步拉取中心配置，成功更新内存中的登录时限，失败保留上次有效值并记录原因，下个周期再尝试。网络请求不会阻塞服务器 tick，存在在途请求时不叠加。计时使用单调时钟，服务器暂停或卡顿会延后拉取。登录时限不写本地 TOML，默认 60 秒由中心数据库初始化；玩家进入时读取一次该值并固定登录期限，之后刷新不改变已进入玩家的期限。

普通 RPC 日志记录 rpc_client_start/end、request_id、method、status 和 duration_ms，可与中心日志关联。项目 RPC 日志不记录正文、完整 metadata 或原始凭据；服务端处理成功与客户端超时可能同时出现，不能仅凭一端日志判断响应已经送达。

## 玩家注册与登录

普通玩家可执行以下命令，控制台不能代替玩家认证：

| 命令 | 行为 |
| --- | --- |
| `/realmmesh register <密码> <确认密码>` | 本地核对两次输入一致后向中心注册，成功即认证当前连接 |
| `/realmmesh login <密码>` | 使用当前游戏名字向中心登录，失败次数由中心统一维护 |

名字从当前玩家读取，命令不接受代填名字。密码格式由中心校验；命令参数保留 `$%&@#^*!` 等允许的特殊字符。每个连接同时最多提交一次认证请求，已登录后不会重复提交。离开服务器会清理状态，重进后必须再次登录。

中心默认允许失败 3 次，第三次失败立即进入 5 分钟休息期，实际参数以中心数据库配置为准。Mod 收到休息结果后立即踢出并显示剩余秒数。休息期内可以重新进入服务器，但再次提交登录仍会被踢出；Mod 不延长截止时间，也不因密码正确而解除休息期。

中心不可用或请求超时会显示固定提示，玩家可以手动重试。客户端不自动重试、不保存密码；取消请求不保证中心事务尚未提交。

未登录及认证请求处理中执行服务端门禁，管理员也不豁免：

- 固定进服位置并允许转动视角，阻止移动、跳跃、载具控制和飞行切换
- 阻止方块、实体及物品交互、攻击、拾取、丢弃、副手交换、背包/容器修改、合成及维度切换
- 禁止聊天及其他玩家命令，只允许直接执行 `/realmmesh register` 和 `/realmmesh login`；服务器控制台不受玩家门禁限制
- 临时免伤和抗推动，暂停饥饿消耗与原版自然回血；不改变游戏模式，不补满状态，不清除状态效果，效果计时继续
- 客户端与服务器均需安装兼容版本的 RealmMesh。客户端按服务器同步的登录布尔状态阻止背包界面及操作输入；服务端仍独立校验，消息不携带密码或服务器凭据

登录超时从玩家进入开始，以中心当时配置为准。重试、错误输入、中心故障和配置刷新都不延长期限；到期断开并取消在途请求，不向中心增加失败次数。仅在配置时限大于对应节点时，发送一次剩余 30 秒和 10 秒提醒；卡顿跨过节点时提示当前剩余秒数，不补发旧提醒。

注册或登录成功立即解除当前连接的门禁。重连需要重新登录；同一网络连接内重生保留已完成的认证，未登录重生不重置截止时间。当前玩家对象被替换时取消旧对象的在途请求，迟到结果不复用。

门禁覆盖原版操作、已接入的 NeoForge 事件及列明的数据包入口。第三方 Mod 自行修改背包、传送或处理自定义网络消息的路径，需要按实际整合包验证，不能视作已自动覆盖。登录后环境伤害继续生效；临时保护仍可能被反复重连利用，本步未增加战斗退出惩罚。

游戏服启动时将 gRPC `NettyClientHandler` 帧日志级别限制为 INFO，避免 NeoForge 默认 `debug.log` 记录认证头或请求字节，项目的请求关联日志仍保留。不要为该记录器重新开启 DEBUG/TRACE。此限制不覆盖原版客户端命令输入历史或其他模组自行记录命令的行为。


## 账户变更通知

游戏服通过现有中心连接订阅账户变更，每个逻辑服务器只维护一条通知流。中心发送响应头后记录订阅就绪；等待响应头沿用 `timeoutMillis` 上限，已就绪的长连接没有普通 RPC 的整体短期限。

订阅正常结束、网络错误或凭据拒绝后，至少等待 5 秒再异步重建。计时由服务器 tick 推进，停顿会延后重试；运行期间订阅失败不踢出已有玩家，不重置登录期限，也不补发断线期间的事件。服务器凭据仍是启动快照，轮换后需更新本机配置并重启。此订阅在既有 Echo 和配置启动检查完成后发起，不新增订阅失败中止启动的规则。

网络回调只保存消息。客户端每次只请求一条，服务器线程取走后请求下一条，避免游戏线程阻塞时持续堆积；这是接收流控，不是消费确认 ACK。每个 tick 最多处理一条通知，停服关闭订阅并丢弃未处理消息。

有效通知按玩家名字忽略大小写匹配，无论该玩家是否已登录，都先清除本连接认证状态、取消在途认证，再踢出。改密提示重新进入并登录；删除提示账户已删除。无匹配玩家时不操作，不记录待踢出列表。非法名字、零值或未知原因只记录固定告警，不踢人。

订阅日志记录服务器 ID、就绪状态、结束状态码和重试间隔，不输出远端异常正文或通知载荷。通知不撤销 HTTP JWT；当前中心尚未接入改密和删除入口，因此正常业务不会自动产生这些事件，需后续补齐发布入口。
