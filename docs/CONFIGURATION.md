# 连接配置与服务器凭据

游戏实例首次启动后生成 `config/realmmesh/connection.toml`：

```toml
[rpc]
host = "127.0.0.1"
port = 9000
timeoutMillis = 2000
server_id = ""
server_secret = ""
```

| 字段 | 说明 |
| --- | --- |
| host | 中心主机名或 IP，不包含协议和端口 |
| port | 中心 gRPC 端口，范围 1–65535 |
| timeoutMillis | 单次请求超时毫秒数，范围 1–2147483647 |
| server_id | 中心登记返回的服务器 ID，必须使用带引号的十进制正整数字符串 |
| server_secret | 中心交付的 43 字符 Base64URL 原始密钥，不是数据库摘要 |

空凭据不会建立匿名 RPC 客户端。凭据格式或类型错误时只显示固定提示，游戏服正常启动。host、port、timeoutMillis 的非法值由 NeoForge 配置系统处理并恢复默认值，TOML 语法错误也由原生配置系统处理。

配置在逻辑服务器启动时形成快照，修改文件后必须重启游戏服务器。配置使用 COMMON 类型，不向远端玩家同步；客户端安装 Mod 后生成的是它自己的本机配置。内置服配置属于运行内置服的本机用户。

## 凭据生命周期

中心管理员预先登记服务器并交付 ID 和原始密钥。原始密钥只在创建或轮换成功时交付，中心不提供恢复接口；丢失时重新轮换。

- 停用后，中心拒绝后续调用；重新启用后原密钥恢复可用。
- 轮换后，旧密钥失效；修改本机配置并重启才能使用新密钥。
- 删除后，该服务器凭据失效。

每次请求自动附带服务器身份、密钥、独立 request ID 和超时设置。当前使用明文 gRPC，没有 TLS；服务器凭据认证不提供链路加密。不要将密钥提交到版本库或发给其他玩家。

## 探测与排查

控制台执行 `realmmesh ping`，玩家执行 `/realmmesh ping`，要求权限等级至少为 2。命令异步执行，在服务器线程返回结果；不会向其他管理员广播结果。显示耗时包含整个调用，不是纯网络延迟。

| 现象 | 检查内容 |
| --- | --- |
| 提示检查配置与凭据 | 字段类型、ID、原始密钥是否正确，修改后是否重启 |
| UNAUTHENTICATED | 中心是否停用或删除服务器，密钥是否已轮换 |
| UNAVAILABLE | 中心进程、地址、端口与网络连通性 |
| DEADLINE_EXCEEDED | 中心响应、网络状况和 timeoutMillis 设置 |

游戏服不等待中心就绪，也不自动重放失败请求。中心恢复后可再次执行命令。停服关闭客户端；玩家退出或服务器停止后的迟到反馈会被丢弃。

日志记录 rpc_client_start/end、request_id、method、status 和 duration_ms，可与中心日志关联。项目 RPC 日志不记录正文、完整 metadata 或原始凭据；服务端处理成功与客户端超时可能同时出现，不能仅凭一端日志判断响应已经送达。
